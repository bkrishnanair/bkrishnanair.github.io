CHALLENGE

The hard part is keeping everything consistent.

A live map is only one part of the product. Capacity limits, waitlists, attendance records, and public event data all need to agree—even when people act at the same time. I owned the application end to end, including its 68 pages, API layer, data model, security rules, and deployment.

Engineering decisions

01

One transaction. A consistent RSVP.

CHALLENGE

Independent capacity checks and writes can race when multiple attendees request the last spot.

APPROACH

Consolidated capacity checks, waitlist promotions, and badge awards into one atomic Firestore transaction.

RESULT

Eliminated RSVP race conditions under concurrent load.

02

Send only what the public needs.

CHALLENGE

Public event responses carried unnecessary fields, and attendee data needed stronger separation.

APPROACH

Introduced field allowlists and moved 566 live attendee records into access-controlled subcollections, with a verification script for the migration.

RESULT

Reduced payload size from 11 KB to 1.5 KB per event—an 87% reduction—with no data lost in the migration.

03

Make background work predictable.

CHALLENGE

Five separate cron jobs and full collection scans added unnecessary operational work.

APPROACH

Consolidated jobs into a fault-isolated dispatcher, removed full collection scans, and added emulator-based security-rule tests with CI gating.

RESULT

A simpler scheduled-work pipeline and automated checks around data access.

04

Treat model output as untrusted input.

CHALLENGE

Generated event content needs to be safe for the product to consume; a successful model response alone is not enough.

APPROACH

Constrained Gemini event generation to a structured schema and validated generations before presenting them to users.

RESULT

AI assistance sits inside the application's validation boundary.

The results

Shipped a live platform serving campus users, with 565+ events, 48 API routes, and 68 pages. The work spans product delivery, concurrency, data access, performance, and operations.

WHAT I TAKE FORWARD

The most valuable work was often below the interface: choosing the transaction boundary, limiting public data, and making migrations verifiable. Those decisions are what let the product evolve with confidence.
